# Video Production Concept

**One paragraph.** This document is the video-side mirror of `docs/CONCEPT.md`: the why and how of the channel's production. The research side (preregs, results, scoreboard) is the source of truth; the video segment is a **downstream renderer of the public record** — it makes the archive watchable without becoming a second source of truth. Every video is a deterministic, reproducible artifact: same committed inputs → same pixels. The reproducibility promise the brand makes about research extends to the frames themselves.

Owner: video agent (this file lives in `videos/` and is maintained by the video side, per the commit boundary in the `video-commit` skill). Research-side context lives in `docs/CONCEPT.md` §7 (tech stack) and §8 (content model); this document does not re-decide those — it operationalizes them.

---

## 1. Brand

- **Data-forward, faceless, minimal motion.** No on-camera presence, no presenter avatar, no stock footage. The visuals are the data: charts, tables, the scoreboard, the commit being sealed.
- **Restrained style.** Our own palette and type, small set of motion patterns (see style spec, §6). If a motion effect explains nothing, it is cut.
- **Determinism is the brand.** For a channel whose credibility is "re-run it yourself," the video pipeline is held to the same bar: pinned versions, checksummed inputs, committed render logs, CI re-render verification. A published frame that cannot be regenerated from the repo is an incident, same as a backtest number that cannot be reproduced.

## 2. Scope and the hard boundary

The video segment **reads** the research record; it never writes to it.

- **Read-only inputs:** `docs/preregistrations/**`, `docs/results/**`, `docs/METHODOLOGY.md`, `docs/CONCEPT.md`, `scoreboard/**`, and the data snapshots/manifests they reference.
- **No new numbers.** Every figure shown on screen must already exist in a published results doc (or in the prereg/scoreboard for recaps). A video that needs a number that doesn't exist yet requests a new prereg from the research side — it never computes one.
- **Never staged in video commits:** `docs/**`, `research/**`, `scoreboard/**`, `agents/research/**`, non-video CI workflows. (Full list: `video-commit` skill.)

## 3. Inputs

Three legitimate input types, all recorded in the build log with checksums:

1. **Results docs** (`docs/results/PR-YYYY-NNN-results.md`) — source for every strategy number.
2. **Prereg docs + scoreboard** — source for recaps (hypothesis, pre-registered bar, seal date + SHA) and aggregate stats.
3. **Derived data extracts** — small files (CSV/JSON series, tables) copied or mechanically derived from a results doc or its pinned data snapshot, stored in the video's `data/` directory. The build log records the derivation (source file, snapshot/checksum, command). Large datasets never enter `videos/**`.

`scoreboard.json` (machine-readable export of the scoreboard, alongside `SCOREBOARD.md`) is the video-side feed for scoreboard segments; it must be regenerated by the research side's scoreboard build so it can never diverge from `SCOREBOARD.md`.

## 4. Per-video layout

```
videos/<video-slug>/
├── spec.md            # the video spec — committed BEFORE the first render
├── composition/       # HTML/CSS/JS (hyperframes)
├── data/              # small derived data inputs + sources + checksums
├── audio/voiceover.wav  # committed TTS output (see §7)
├── thumbnail.png      # rendered frame + pinned overlay (see §7)
└── build.log          # regenerated every render; committed with the change
```

Shared things — templates, style spec, render script, TTS glue, fonts — live in `videos/pipeline/`, versioned. A video's build log names the pipeline (template) versions it used; a video never vendors a copy of a template.

### 4.1 The video spec (the gate)

`spec.md` is the video-side analog of a preregistration, at video scale. It is committed **before the first render** of the video, and a video whose spec is not committed is not rendered. Contents:

| Field | Contents |
|---|---|
| **Meta** | Slug, series (Portfolio / Seal / Verdict / Build log / Meta), working title, target runtime, pipeline version |
| **Beat sheet** | Ordered beats: on-screen content, narration intent, duration target, template block used |
| **Number citations** | Every figure the video will show, with its citation: PR ID + results-doc path (or prereg/scoreboard for recaps; CONCEPT/METHODOLOGY for rule descriptions). No uncited number |
| **Inputs** | Data files with checksums, prereg/results/scoreboard SHAs cited |
| **Standing items** | Disclaimer card (pinned, verbatim §10 of CONCEPT), scoreboard segment (if any), channel outro |

Amendments: pre-first-render, edit freely. After the final render, a spec change that alters shown content requires a re-render, a build-log note, and an amendment entry in the spec with a justification — append-only, mirroring the research rule.

## 5. Lifecycle

```
SPEC → DRAFT → REVIEW → FINAL → PUBLISH
```

1. **SPEC** — spec.md committed (gates everything).
2. **DRAFT** — render(s); iteration allowed; each material render updates the build log's draft section.
3. **REVIEW** — owner watches the draft against the spec. Feedback loops to DRAFT. This is the only human-judgment step; the spec is what makes the review fast and checkable.
4. **FINAL** — final render. Build log updated to final state **in the same commit** as the change it describes. CI re-renders the committed directory and verifies the output hash matches — a mismatch is an incident (fix the pipeline; never hand-edit the output).
5. **PUBLISH** — a dated, manual owner act (YouTube upload). The publish event — date, video URL — is recorded in the build log in a follow-up commit. Nothing publishes itself.

Cadence, series mix, and the seal→verdict gap are set by `docs/CONCEPT.md` §8 and are not re-decided here.

## 6. Style spec (versioned, separate file)

`videos/pipeline/style/style-spec.md` — the "what" (this document is the "why and how"). Versioned (semver); every build log pins the style-spec version. Contents:

- Palette (limited: background, text, one accent per series verdict color — confirmed / falsified / inconclusive), typography (two pinned fonts + sizes), spacing.
- Motion rules: which transitions exist, their durations, "no motion unless it encodes something."
- Chart conventions: axis style, cost-adjusted vs. raw series handling, how the pre-registered bar is drawn on the chart (it is always drawn), how a falsified result is shown (same production values, verdict color, no euphemism).
- The **pinned disclaimer card**: exact text of CONCEPT §10, rendered identically in every video. Same pixels every time — an integrity anchor, not a decoration.

## 7. Pipeline and determinism

- **HyperFrames** (HTML/CSS/JS → frames → FFmpeg). The render script lives in `videos/pipeline/`, is invoked with only the video dir as input, and emits output + checksum.
- **Pinned versions** (recorded in the build log): hyperframes, FFmpeg, fonts, template versions, style-spec version, TTS voice + model + settings, data input checksums.
- **TTS (ElevenLabs v3)** is generated **once** and the wav is committed to `audio/`. The render consumes the committed wav, so re-renders are deterministic and cost-free; the text→wav step (voice, model, settings, script hash) is recorded in the build log. Regenerating a voiceover is a deliberate, logged act.
- **Thumbnails are composition frames** + a pinned overlay style from the style spec — regenerable from the repo, no hand-made art.
- **Music: none.** Optionally one permanently pinned, verifiably owned/CC0 track. Licensing and taste drift are both out of scope for the brand; voice + restrained motion is enough. (Recorded as a standing decision; a change is an owner decision, not drift.)
- **CI:** re-render on merge for `videos/**` changes; re-render hash verification on FINAL; scoreboard segment data checked against `scoreboard.json` (numbers in the video must exist in the file).

## 8. Series → templates

One versioned template family per series, in `videos/pipeline/templates/`, each defining the structural beats. A video picks a template family and version; the spec records it.

| Series | Template beats |
|---|---|
| **Portfolio** | What's in it → what the data says → what changes and why → (if it becomes a hypothesis) the prereg it feeds |
| **Seal** | Mechanism → data & caveats → the bar it must clear → falsification notes → **the commit sealed on camera** (SHA shown on screen) |
| **Verdict** | **Prereg recap** (hypothesis, pre-registered bar, seal date + SHA — self-sufficient per CONCEPT §8) → the run → numbers against the bar (bar drawn on chart) → scoreboard update → honest read; falsified adds a **post-mortem** beat; confirmed may end with the pin decision on screen |
| **Build log** | The machine that makes this channel: components, what was tried, failures included |
| **Meta** | Methodology deep-dives, retrospectives, state of the scoreboard |

The **scoreboard segment** is a data-driven composition that renders from `scoreboard.json` — state-of-the-scoreboard episodes are rebuildable whenever the archive changes without new composition work.

## 9. Integrity rules (video side)

Local equivalents of the research rules; full commit discipline in the `video-commit` skill:

1. **One video = one directory.** No video content outside `videos/<slug>/`; shared pieces stay in the pipeline, versioned.
2. **Spec gates render.** No committed spec, no render (§4.1).
3. **Numbers trace.** Every on-screen figure is cited in the spec and build log to a results doc (or prereg/scoreboard for recaps). Nothing computed in the composition.
4. **Build log is regenerated, not narrated.** Every render updates it: timestamp, composition + template + style-spec versions (git SHAs), data inputs with checksums, TTS voice/model/settings, committed-wav checksum, encoder settings, publish record. Same commit as the change.
5. **Deterministic builds.** Re-render of the committed directory reproduces the published pixels. Mismatch = incident: fix the pipeline, fix forward, publish the incident.
6. **No raw data dumps** in video dirs — small derived extracts with source + checksum only.
7. **No history rewriting** on pushed commits.
8. **The boundary holds.** Refused paths are refused (§2); a video commit that stages one is aborted, not cleaned up quietly.

## 10. First video (Phase 0)

**Rules/methodology explainer (Meta series)** — "How this channel works: preregistration, the seal, the verdict, the scoreboard."

- Unblocked today: no results doc needed. Its citations are CONCEPT.md and METHODOLOGY.md (rules, lifecycle, what preregistration does and doesn't fix — the §1 disclaimer beats become a full segment).
- Builds the entire pipeline end-to-end: spec gate, template family (Meta), style spec v1, render script, TTS glue, build log format, CI re-render verification — against the cheapest possible content.
- Every later video's recap and disclaimer beats reference the rules this video establishes; making it first means the channel's first artifact is its own method, which the brand claims.

The benchmark-study episode (PR-2026-001) is the first *data* video; it lands when the results doc exists, and it is the first exercise of the number-tracing rules at full strength.
